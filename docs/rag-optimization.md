# RAG 检索

知识库包含18份演示政策、76个片段。每份文件首行为标题，后续每个非空行形成一个片段，保留来源与编号。

```text
问题 → BGE向量召回 + BM25召回 → RRF融合
→ 交叉编码器重排 → 阈值过滤 → Top3锚点
→ 同源条款补全 → 返回证据 → 回答与引用
```

## 模型与参数

| 配置 | 默认值 |
| --- | --- |
| 向量模型 | BAAI/bge-small-zh-v1.5 |
| 向量库 | Chroma |
| 重排模型 | BAAI/bge-reranker-base，版本在代码中固定 |
| 候选池 | 12 |
| 重排阈值 | -2 |
| 重排锚点数 | 3 |
| 补证正文预算 | 1800字符 |

`.env` 中的 `SUPPORTPILOT_RETRIEVAL_STRATEGY`、`SUPPORTPILOT_RAG_POOL_SIZE` 和 `SUPPORTPILOT_RERANK_THRESHOLD` 控制检索。保留 `vector`、`hybrid`、`hybrid_rerank` 三种策略供对照。

## 同源条款补全

短政策按行切分后，一般规则和限制容易分离。三个固定漏检中，手机条款在融合阶段丢失，金卡与跨品类限制被重排 Top3 截断。单纯降低阈值无法补齐这些条件。

当前实现保留重排锚点，从命中的同一文件中补充相邻条款，按距离优先、来源轮流分配正文预算。补充项放入 `context_chunks`，使用各自的真实 ID 和来源，不继承锚点分数。

原始锚点不裁剪；1800字符预算不包含 JSON、元数据或历史消息。该方法增加回答输入长度，但不增加模型节点。相关文件完全未命中、文件过长或预算不足时仍可能漏检。阶段数据见[漏检诊断](history/2026-10-22-rag-miss-fix.md)。

## 与回答的关系

政策工具返回 `found`、`no_evidence` 或 `error`。回答需要核对证据是否支持问题；活动名不能当成品类限制，空结果不能通过条件句补造政策。

多轮对话通过[证据检查](policy-evidence-refresh.md)决定重新检索或复用。复用 ID 由程序校验，语义是否覆盖最新条件由模型判断。最新验证见[评测总览](evaluation.md)。
