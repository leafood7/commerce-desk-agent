# 三条演示流程

按[运行说明](../LOCAL_SUPPORTPILOT.md)启动网页与 API，确认模型缓存和政策索引可用。每条流程使用新会话。在线输出有波动，演示前先预演；若改用保存的轨迹，注明为历史运行结果。

## 1. 政策问答与无依据回答

| 输入 | 检查点 |
| --- | --- |
| 手机只是开箱看了一眼，没有激活，就不能退了吗？ | 说明合理开箱不当然失去资格，保留期限、完好及购买提示条件；引用数码与通用退货政策 |
| 黑金会员每年会费多少元？ | 费用未收录，明确无法确认，不编金额 |

展示工具返回的片段和最终引用，解释“检索相关”和“足以回答”的区别。订单工具没有激活或实物完好字段。

## 2. 条件更正与证据复用

依次输入：

1. 我的券过期了。
2. 我看错了，还没过期，券面写仅限食品，我想买显示器。
3. 再简单解释一下。

第二轮应按最新有效期和明确品类限制取证，回答不能用于显示器。第三轮检查已有证据，足够时复用真实 ID，不新增检索。

补充边界问题：“券名叫食品节活动券，但我不知道适用范围。”此时名称不能当作限制；有一般条款时给条件结论，缺少证据时说明无法确认并请求券面范围。

## 3. 加急审批与重复批准

网页演示前确认演示订单已付款、待发货且超过 `promised_ship_at`。提交加急后，在审批区处理；聊天中的“批准”不能替代审批操作。

也可使用临时库运行审批图：

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python.exe scripts/demo_shipping_workflow.py
```

| 场景 | 预期 |
| --- | --- |
| 等待审批 | pending，工单数0 |
| 批准 | 工单数1 |
| 再次批准 | 返回同一工单，数量仍为1 |
| 等待期间订单改为运输中 | 批准前复查，申请失效，工单数0 |

结果写入 `work/demo-shipping-result.json`，现有订单库不变。这是审批图的程序演示；工单只保存在本地。

## 技术说明要点

- 上游提供服务、会话和模型接入基础；项目新增电商业务、RAG、证据检查、MCP 与评测。
- 短政策的限制被切到相邻片段时，采用同源补证；代价是输入变长，相关文件未命中时仍会失败。
- 只对明确问候和纯查单省去证据检查，更正与复述保留语义核对。
- MCP 统一只读工具接口，LangGraph 编排流程；审批资格、事务和去重由程序执行。

独立 MCP 演示可运行 `scripts/verify_mcp_tools.py`。架构细节见[调用链](architecture.md)，效果与成本见[评测总览](evaluation.md)。
