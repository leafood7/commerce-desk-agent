# 知识维护闭环：解析修订、审核、检索与FAQ换版

2026-11-01。交付整个知识维护能力组；不是把前面的测试和界面修补拆成多个阶段。源码走读仍暂停，本轮无付费模型调用、数据库迁移、commit或push。

## 针对什么问题

旧系统能上传、检索和阅读政策，却不能在页面说明某段解析哪里错了、如何修正、谁批准了这项修改。FAQ仅依赖来源当前有效性，回退政策还可能让旧FAQ再次看似有效。本轮补齐从发现解析错误到安全发布的维护流程。

## 完整操作链

1. 管理员在知识库打开“核对解析”，查看带段落、标题和页码位置的文本，对照下载的原文件修改。每次最多12段、每段20000字符，必须填写有效原因；过长段落提示重新上传，不能无声截断后编辑。
2. 提交生成同一文档的新版本，保留原文件与哈希、基准版本、原段落哈希、前后差异、提出者和时间。不直接修改线上片段，不让模型补写来源。
3. 后台重建新版本的父子块和向量索引。索引失败时旧版本继续有效，失败版本不能发布。新入库版本保存准确的解析快照；以后解析器代码变化不会重写当时的快照。
4. 另一位有approver权限的账号查看差异，填写审核原因，批准或驳回。修订者不能自审；审核只确认本次修订，不等于发布。普通上传入口保留原有管理员发布规则，不将本轮独立审核扩大表述为所有文件上传的强制流程。
5. 管理员发布已批准修订版，程序重新核对基准来源和配置指纹，再切换当前版本。检索和原文阅读都使用新文本，旧引用不能作为当前回答依据；页面和工具标明“人工修订解析”，不伪装为上传原文件的逐字内容。
6. 所有依赖旧来源的FAQ版本（包括正在处理的草稿）持久标记待复核并停止检索。维护者核对FAQ正文和新来源后上传、发布新FAQ版本，才恢复使用。系统不自动改FAQ答案、不偷偷替换引用。
7. 回退要求目标曾发布、属于同文档、当前仍有发布状态、目标现在有效，且当前版本符合操作者看到的版本。人工填写原因并记录审计；撤回后不能借回退重新上线。回退不会清除旧FAQ的复核要求。

## 一致性与边界

- 发布、审核和回退使用商家级事务锁；来源变化后，陈旧修订被拒绝。FAQ失效与发布处于同一事务。
- 后台索引完成与来源换版可能同时发生。FAQ失效记录加锁并在工作线程完成时保留，防止完成索引覆盖“待复核”标记。
- 不覆盖已发布索引；新版本有独立片段标识。旧索引保留用于追溯，查询由数据库当前发布状态过滤；本轮未做历史向量物理清理。
- 新文本仍不能证明订单事实、退货资格或真实退款。已有退货规则映射不自动迁移，需管理员重新核对；旧流程继续办理时依然检查当前来源。
- 原文件没有被改写，解析修订可能包含人工错误。权限、哈希和审核流程不能证明补写条款真实，审核者仍须逐字核对原件。
- 旧版本没有解析快照时按当前解析器重新解析，不能宣称完全恢复历史解析行为。新版本才具备本轮增加的持久解析快照。仅修订已有段落正文，不提供任意页码重排、复杂表格重构或自动OCR修复。

## 实测结果

较广回归79项通过，213.21秒。最终相关回归36项通过，62.24秒，其中15项为修订专项；两批重叠，不相加。覆盖：未审核拒绝发布、同角色越权与跨组织拒绝、陈旧/重复/空白修改、无效原因、指纹不符、驳回终态、索引失败、连续修订、原文件字节不变、快照损坏阻断、原文与检索换版一致、FAQ新版本恢复、回退后FAQ不复活、撤回/过期目标拒绝回退，以及FAQ索引过程中来源变化。

最终候选浏览器完整流程1项通过，约9.74秒。这是自动化脚本耗时，不代表人工审核工时。实际使用MySQL、BGE、Chroma、重排和HTTP MCP。演示用明确的解析器替身丢掉原文件中已有的“定制商品除外”，随后在页面修订，用另一审核账号批准，管理员发布。验证实际检索得到新例外，旧FAQ检索为空，新FAQ发布后可检索，回退后又停止检索；下载原文件哈希始终不变。

两个角色由自动化脚本控制，不是独立第三方人工审查；不据此声称模型准确率或真实客服效率提高。未发现并宣称修复真实PDF解析器缺陷，测试中的丢条款是主动注入的故障。

浏览器暴露并修复了未修订版本的空记录导致面板渲染错误，新增回归断言。测试脚本还处理了模型未预热、相同文件被正确去重复用旧标题的准备问题。所有问题都合并在本阶段记录，没有另写小总结。
