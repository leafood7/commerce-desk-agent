# 会话恢复与受控配置版本

日期：2026-10-29。实际代码目录：D:\VScodeProgects\commerce-desk-agent。本轮未提交/推送，没有购买或部署服务器。

## 做了什么、补充什么

实现管理员创建草稿、发布配置、乐观发布序号及审计。草稿不生效，已保存版本正文不可编辑，更新创建新版本。创建运行时同事务保存不可变快照；后来发布的新版本只影响新运行，不覆盖已排队、暂停或审批中的旧流程。

工作台新增“配置版本”。只开放服务端白名单别名、受控intent_v1模板、128/256输出上限、1—3检索候选、标准/友好用语。没有自由提示词正文编辑、多供应商注册、地址/密钥/权限/审批/配额覆盖。默认只有规则模式；服务端未启用模型时，页面不能替它开启模型。参数真实接入：候选数传入知识工具、输出上限传入模型适配器，用语只在已校验结果外增加问候。

保存模板及配置指纹、私有模型绑定指纹，记录运行的版本。服务端关闭模型、变更绑定/模板或收紧输出限制时，快照不能绕过当前限制。旧流程缺少快照时标明legacy_unrecorded，不伪造历史配置，保持规则模式。实际供应商修订号未作为本轮可复现能力交付。

新增“会话记录”：本人会话、最新公开消息、加载更早消息、近期流程、同会话新任务及打开已有售后流程。恢复不新建或重跑业务任务，活动流程只续订进度；切换/退出清理订阅。新任务明确清空旧输入，恢复回显原需求，避免隐藏条件串用。新问题保存全文，旧已截断记录不补造。

消息分页改为时间+ID游标，校验游标属于本人当前会话；仅查询已公开消息表，不读取图检查点或凭证。历史助手回答不自动进入模型上下文或本轮政策证据。这是会话归组和可恢复界面，没有声称语义长期记忆或上下文摘要已完成。

## 意义与针对性价值

解决“管理员改配置后，排队/恢复运行悄悄换参数”“界面有设置但执行不使用”“只能看近期运行下拉，无法串起同一会话”“恢复又创建一份任务”“新任务误用旧表单条件”等工程问题。现在可核对运行实际绑定的安全参数与版本、按原运行继续，并看见完整公开记录；没有编造客服准确率或线上业绩。

技术包括FastAPI角色/组织/所有者校验、Pydantic额外字段拒绝、SQLAlchemy同事务快照、MySQL发布互斥与修订冲突、Alembic新增表、LangGraph恢复/模型降级、React/TypeScript状态绑定、可取消SSE、游标分页和Playwright。

新旧配置只在演示商家验证，测试后恢复原有效设置；初始无发布版时使用等价默认版恢复，版本与审计历史保留，不删除记录。没有使用真实模型评估新参数的语义质量；不能把参数传输正确当作回答质量提升。

## 实际困难和处理

难点是配置的时间边界：发布指针可变化，但旧运行必须稳定；当前服务端权限收紧又必须高于旧快照。通过运行快照、绑定指纹及关闭/变化保护区分“原来选了什么”与“现在允许做什么”，不把密钥和地址存入公开配置。

另一难点是会话恢复时的异步回写和隐藏输入。恢复原需求、准备新任务清空、取消旧订阅、按流程绑定显示，并用浏览器校验恢复不会创建任务。消息相同时间戳的游标用ID补充排序，且拒绝其他会话游标。

单独重建最终前端时，我漏用了项目已有命令行代理，Docker匿名授权超时；补上既有本地代理后构建与验收通过。没有更换不可信镜像源或关闭TLS。失败构建日志保留。本轮没有出现业务回归失败，构建故障不包装成业务或模型效果改善。

## 如果由你实现，会遇到什么困难

容易把“数据库存了版本”当作真正生效，worker仍读取最新环境；或把整份BaseSettings连同密钥序列化。也容易让旧快照覆盖新的权限限制，或把历史助手回答当作事实输入。建议先写“先创建、后发布、再执行”的对照，实际检查工具参数/模型请求，而不是只检查表和界面文案。

会话部分要区分打开原运行与创建新运行，处理游标归属、同时间戳并列、前端旧请求回写。用请求计数证明恢复没有重复POST，结合原问题回显与缺字段暂停验证，不只是截图。
