# 知识更新联动使用说明

## 可以完成什么

政策发布、撤回、回退或整理条款更新后，系统记录一次知识更新，并为受影响的 FAQ、政策整理和退货规则建立关联待办。旧内容失效只是起点，工作人员可以从待办继续修订、审核和发布。

入口：工作台 → 知识库 → 知识更新待办。管理员负责修订与发布，审批员独立审核。客服不能维护这些内容。

## 完整操作

1. 上传并处理新版政策，发布前打开影响预览，核对差异、关联 FAQ、政策整理和退货规则。
2. 确认发布后，查看知识更新待办。原有过期 FAQ 不再参与正常检索。
3. 打开 FAQ 待办，查看旧答案和当前有效原文，修改答案、适用对象并填写原因，生成新的 FAQ 版本。
4. 等待解析完成，由另一审批角色批准或退回。未经批准，关联草稿不能发布。
5. 管理员发布已批准的 FAQ，新版本进入检索，对应待办完成。保留旧版本及处理记录。

本轮实际操作使用隔离演示政策：期限从7天改为9天；完成影响确认、FAQ修订、独立审核及发布，并能检索到新答案。没有调用真实模型接口。

## 其他关联资源

- 政策整理：从待办为当前原文准备候选，沿已有编辑、独立审核、发布流程处理。
- 退货规则：审批员明确确认替代规则。替代项必须有有效证据、属于当前政策版本、退货分支一致并覆盖原商品范围。不会自动改写正在办理的退货申请或旧审批。
- 暂不处理：管理员填写原因后可关闭待办；关闭不会使旧 FAQ 重新有效。
- 撤回、回退：保留历史和待办。恢复某个政策版本，不会自动恢复已经失效的 FAQ；需重新核对。

## 更新过程中的保护

FAQ草稿绑定其原文版本和整理版本。审核期间来源再次变化，旧草稿不能继续作为有效更新发布。异步入库也会保留失效标记，不会因处理结束而重新启用过期内容。政策更新、关联待办与发布状态在同一数据库事务中记录。

影响预览最多检查200个片段、展示60组差异；超出时明确标记截断。FAQ编辑内容上限80000字符。运行影响数量仅覆盖明确绑定相关规则的未结束流程，不代表所有历史Agent。

## 实现与边界

主要实现：`src/workbench/knowledge_updates.py`，数据库迁移`0011_knowledge_updates`，工作台知识更新与影响预览组件。

这是有人工审核的知识维护流程，不是自动理解并改写所有政策。原文已撤回、范围冲突或版本变化时，需要工作人员处理后继续。通用手工FAQ上传入口仍保留，独立审核约束适用于本流程生成的关联FAQ。功能自检覆盖更新、回退、审核、权限隔离和后台处理，不构成模型效果或准确率结论。
