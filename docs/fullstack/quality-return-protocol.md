# 质量问题退货与同文档条件／例外：实现前标准 v1

作者开发验证，不读取封存最终题、不新增付费调用、不宣称独立盲审。先建立标准和题集，再实现。

业务要求：明确选择 no_reason／quality_issue；政策分支不匹配必须阻止。无理由分支仍按7天及未使用条件；质量问题演示分支按单独配置的30天及明确缺陷结论，不能从“质检未通过”或用户自述推断缺陷。已使用及超过7天仅可在质量问题分支满足其自身全部条件后继续。未知签收、超过30天、无明确缺陷、新工单待处理、结果撤销均不得通过。分支更正必须重新读取政策、事实及预览；旧幂等键不能改输入。

兼容：旧请求和旧质检结果默认无理由／缺陷结论未知；不能把历史 failed 回填为 defect_confirmed。迁移仅新增字段，容器升级前备份。审批和模拟受理仍重查。

RAG：冻结24条开发题、3份合成资料。比较同版本召回与分支条款投影，使用真实本地向量／BM25／融合／重排，不调用生成模型。业务绑定来自明确选中的管理员政策，不来自评分答案。投影只能从本次实际召回且已校验的来源中抽取该政策绑定原文，不能补造召回；无关分支、缺原文和更正分别验证。

保存原始候选、实际上下文、必要原文覆盖、同文档错误分支片段、上下文长度及耗时。交替运行；报告冷启动与缓存影响。引用覆盖和片段隔离不等于结论正确。未知事实题仍可能返回政策，必须保留实际工具字段缺失的说明。

必须覆盖：两分支的使用／期限差异、缺陷未知与否定、显式分支更正、策略绑定不匹配、撤销、跨商家、虚构引用、投影不从未检索来源补充，以及正常无理由业务回归。验收包括SQLite、相关MySQL、真实容器和浏览器链路。
