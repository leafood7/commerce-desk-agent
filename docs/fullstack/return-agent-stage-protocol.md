# 退货 Agent 与 RAG 开发对照标准

冻结日期：2026-10-29，实施基线 `1e8f369`。本文件先于候选代码建立，不读取原封存最终测试题。新增样本全部为作者编写的开发场景，不称盲测或独立评审。

## 目标与版本

验证模型能否根据真实只读观察选择下一次查询或补问，同时保留原有确定性业务约束。比较现有规则/检索基线、受限决策和政策版本范围收窄；模型与检索因素分开记录。

RAG固定语料和24个开发问题（按6个政策家族组织）；每题标注必要原文、不可套用资料及是否可回答。比较同一切块、向量模型、召回池、重排和上下文预算，仅改变是否按应用中已知的政策版本收窄。版本来自业务政策绑定，不从题目的标准答案反推；对无有效绑定的题不能用金标准挑文档。

决策合同使用离散动作：查订单、检索政策、检查退货条件、补检、询问商品状态、交还程序预览或结束。只能选择当前观察允许的动作，不能生成工具参数、资格结论、金额、审批或写入指令。所有写入由既有确认/审批节点控制。

## 检查与评分

- 决策：格式有效率、合法动作率、规则回退率、工具/模型调用数、用量与延迟。允许多条合法顺序，不以吻合唯一脚本冒充正确。
- 业务：正常任务能进入确认；缺条件应询问；更正后不复用旧观察；不适用/空检索不能提交；拒绝审批及真实状态保持正确。
- RAG：必要条款覆盖、来源命中、不适用片段比例、无证据误召回、上下文字符数、p50/p95时间。引用存在不等于语义回答正确。
- 固定输入与配置，逐题交替运行版本；保留全部轨迹和退化，不挑选重复中的最好结果。机制替身测试与真实索引/真实模型结果分开。
- 本阶段不自动默认启用模型或收窄检索。开发样本出现改善只能支持下一步验证，不能外推线上效果。

## 执行与预算边界

每个新退货流程最多6次模型尝试，受原有累计token预留与活跃执行时限共同约束，补充/重启不重置。相同观察缓存决策，崩溃留下的未知调用不自动重放。提示版本、配置与模型绑定在创建时固化；旧流程缺新快照时保持规则图。

日常验证用明确模型替身与本地模型索引。若开展真实模型小批次，沿用已授权5元总额度（包含前期该授权下的调用），计入原100元总账；调用前按既有保守账本预留，未知用量不按零。最多24次新模型请求；费用或次数任一达到限制即停止。没有有效费用依据或可用授权余额时只完成离线对照，明确留下真实模型验收缺口。运行时默认规则，不因评测授权启用付费服务。

本阶段不提交、不推送，不接真实退款，不新增部署组件。只有形成可独立验收的能力跨越后再写第7篇总结。
