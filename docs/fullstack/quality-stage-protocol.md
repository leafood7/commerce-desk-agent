# 质检业务闭环：开发前验收标准（v1）

范围：本地演示质检工单，订单商品行和数量绑定；客服创建、审批角色处理、管理员撤销；MCP 只读查询；退货 Agent 等待及刷新。无真实物流、质检设备或退款；不新增付费调用，不读取封存最终题。

先按以下开发场景验收，再整理结果；全部为作者开发测试，不宣称独立盲审或线上准确率。

1. 同键同参数创建返回同一工单，同键不同参数冲突。
2. 不同商家无法读取或处理对方工单，商品与订单不匹配不能建单。
3. 数量须为严格正整数且不超过订单数量；结果不能迁移到另一数量范围。
4. 客服不能登记结果；处理人不能处理自己创建的工单。
5. 只能 requested → in_progress → completed；完成后不能直接覆盖结果。
6. 更新须带当前修订号；旧修订或重复并发处理冲突；处理事件保留。
7. 管理员可撤销工单，需原因；撤销结果不再满足规则。
8. 当前结果取指定商品行和数量的最新工单；新工单等待时不回退使用旧结果。
9. passed／failed 为明确结果，inconclusive 仍未知。原始描述、政策原文不能充当结果。
10. 政策明确配置 recorded 或 passed；recorded 不擅自要求通过，passed 对 failed 阻止申请。
11. 质检记录进入预览摘要；确认后结果被撤销或替换，提交／审批／模拟受理重新校验。
12. MCP 入参固定业务范围，不接受模型自报结果；输出校验绑定、状态和结果。
13. 缺少所需质检时，Agent 等待而不建单；用户刷新后重新读取事实和政策。
14. 明确只读查询只展示结果及演示来源，不进入申请确认。
15. 正常无质检要求的退货不增加质检工具调用；原有审批与数量控制保留。
16. 前端能创建／开始／登记演示结果，Agent 能等待及刷新；工具步骤可见；原有回归通过。

保留基线为上一阶段完成的未提交工作区及其报告；本次不声称完整冻结部署。新增迁移只建表，不删除原数据；真实容器升级前备份。危险或破坏性操作另行决定。
