# 长上下文管理使用与边界

完成：2026-10-30；冻结标准：2026-10-29。适用于新工作台的售后意图路由与受限退货动作模型入口。旧Streamlit/toolkit入口保留原行为。

## 输入怎么组装

每次保持系统约束、当前完整问题、最新结构化条件、实际工具观察和本轮必要政策文本。最近历史作为单独的不可信导航数据插入当前请求之前，不替代条件、政策、质检或审批。当前工作台的模型只分类或选择合法动作，不自由生成最终业务结论。

以前`decision_observation`会截问题360字符、原因120字符、每证据最多500字符和总1200字符。本轮取消这些静默截短。必要内容放不下时，模型HTTP不发出，交还原有确定性规则路径；业务状态与审批仍由原服务重验，不把模型输入过长直接等同拒绝客户的退货资格。

历史按组织、用户、会话及本次明确订单隔离；更正到其他订单的旧流程整体排除，较晚创建的新运行不影响旧运行恢复。没有当前订单时，不从历史猜订单。切单而没有明确提供的新条件清空，当前图中已经明确的条件保留。

## 历史和摘要

SQL读取最近80条加1条用于检测截断；近期最多4个完整对话单元，较早最多12项用户原话提取摘要，每项最多120字符并标记是否截取、原消息和运行ID。原始消息始终留在数据库；窗口以外明确标为省略，不能声称摘要涵盖所有历史。

这是确定性提取摘要，不调用摘要模型，也不自动理解任意旧自由文本的业务含义。关键字段来自当前图状态或本轮结构化输入；摘要中的“已批准/已退款”仍是历史说法。实际状态由业务工具查询。工具调用和结果作为完整单元保留或整体丢弃，缺失配对的单元不进入模型。

## 预算

|服务端参数|默认值|含义|
|---|---:|---|
|WORKBENCH_CONTEXT_INPUT_TOKENS|6000|单次输入的保守上界预算|
|WORKBENCH_CONTEXT_HISTORY_TOKENS|1200|近期历史序列化字节上界预算|
|WORKBENCH_CONTEXT_SUMMARY_TOKENS|600|摘要序列化字节上界预算|
|WORKBENCH_CONTEXT_RECENT_UNITS|4|近期完整对话单元上限|
|WORKBENCH_CONTEXT_SUMMARY_ITEMS|12|旧用户原话摘要上限|
|WORKBENCH_CONTEXT_HISTORY_ENABLED|true|是否把辅助历史放入模型输入|

使用UTF8字节与框架预留作保守token上界，不是DeepSeek精确tokenizer；不会将此数当供应商实际用量。输入还受既有单次预留减输出空间的约束，累计调用/token配额继续独立生效。先保完整必要输入，再放最近单元，最后放摘要；不够就整体移除可选单元。

## 保存、观察与界面

现有私有`wb_flow_actions`保存`__context__:`前缀的有指纹版本快照，无数据库迁移。快照记录来源、覆盖、预算和算法配置；从当前SQL原文重建，不以旧快照作为事实。内部快照不占用户继续次数上限，用户不能用保留前缀构造继续动作。模型缓存保留原未知调用不重放规则，并绑定上下文指纹。

登录后`GET /api/v1/runs/{id}/context`只返回本人该流程的公开说明，包含最近条件、未知项、是否省略历史和预算状态。不会返回摘要正文、旧消息、私有checkpoint或模型草稿。相同公开字段随最终输出和SSE发布。新工作台“售后助手”和“退货申请”显示“最近核对的信息”；修改表单后需重新核对才更新。

旧的已结束流程不批量补写上下文；新流程或继续核对会生成。浏览器登录凭证保持既有内存设计，刷新后需要重新登录，再恢复流程；SQL中的上下文和业务记录不丢失。
