# 架构决策核对：先复用，按证据决定迁移

原方案：PostgreSQL检查点、Celery+Redis队列。
实际：MySQL/SQLAlchemy检查点与事务持久队列，独立文档worker和run-worker。

收益是当前本地交付减少额外关系库与消息组件，业务及任务状态可共享事务边界；代价是项目自行承担租约、恢复、序列化兼容和队列调度维护，不能等同上游通用持久化实现。现有文档明确单API/有限状态图边界，不声称通用子图或生产多副本能力。

本轮不迁移这些组件。后续10会话+2任务验收和恢复测试给出证据；如需多副本和更复杂队列再单列选型决策。Redis可在明确缓存、限流、短期副本职责后引入，不作为业务唯一存储。此处为架构偏差说明，不宣称已经完成迁移或生产规模验证。
