# 质量问题退货与条件／例外证据约束

本阶段将演示退货拆成显式的 `no_reason` 与 `quality_issue`。这是管理员配置的合成商家规则，不是对真实平台、法律权利或线上准确率的陈述。

## 业务行为

默认无理由分支仍按原规则核对期限及未使用条件。质量问题分支有单独的期限和条款绑定；演示种子配置为实际签收30天内、允许已使用，但必须有同商品行、同数量的明确缺陷确认。分支与所选政策不一致时阻止办理，不会自动把质量问题例外套到无理由申请。

质检工单新增 `finding`：明确存在缺陷、未发现缺陷、无法确定。它独立于旧的 `verdict`；旧记录的“未通过”不回填为确认缺陷。新增明确判定必须与检测结果一致，登记权限仍属于独立处理人。缺少明确判定时 Agent 等待；未发现缺陷时不满足该质量问题规则。

用户可以在预览阶段显式更正分支及政策，程序重新读取事实、检索条款并生成新预览。确认、批准与模拟受理继续重查。前端分支选择是明确业务输入，不声称已实现通用自然语言意图理解。用户说“坏了”、提供照片或选择质量问题，都不能代替缺陷记录。

## RAG 实现

新增实验模式 `clause_bound`：限定当前业务政策的版本，取得实际检索结果并验证来源后，才从这些结果中提取管理员绑定原文，记录来源摘要、原话及字符位置。相同文档的其他分支不进入模型动作上下文。原始引用保持原样；界面区分当前分支原文与完整来源。

投影不从未召回来源补内容，也不把空投影回退成完整无关资料。缺必要来源时沿用最多一次补检，仍不足则停止；没有模型自动修复或额外付费调用。默认检索模式没有被实验结果自动修改，管理员可选择实验模式发布新配置。

## 本地演示

1. 管理员选择 `guided_v3`、规则模式及“按当前分支组装已召回原文”后发布。
2. 新演示数据包含签收10天的 `quality_window` 订单，以及三种政策：普通无理由、要求质检通过的旧演示分支、要求确认缺陷的质量问题分支。
3. 客服选择签收10天的订单、质量问题分支、对应政策及“已使用”，启动 Agent；缺陷未知时会等待。
4. 客服建质检工单，审批角色开始处理并选择“独立缺陷判定＝明确存在缺陷”，填写说明后登记。
5. 客服刷新 Agent，可看到质量问题分支的期限、条件原文及新预览，仍需确认与审批。
6. 确认前更正为无理由分支及普通政策并重新核对，将触发期限／未使用条件限制，不沿用质量问题例外。

## 可复现实验

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONPATH='src'
$env:HF_HUB_OFFLINE='1'
$env:USE_FAKE_MODEL='false'
.venv\Scripts\python.exe scripts/evaluate_quality_return.py validate --output work/quality-return-v1/unused
.venv\Scripts\python.exe scripts/evaluate_quality_return.py run --output work/quality-return-v1/new-rag
.venv\Scripts\python.exe scripts/evaluate_quality_return.py run --supplement --output work/quality-return-v1/new-supplement
.venv\Scripts\python.exe -m pytest tests/workbench/test_quality_return.py -q
```

输出位置必须不存在；无效或重复题号在初始化模型和写输出前拒绝。冻结题集为24条作者开发题、3份合成资料，其中20条政策题、4条未知事实题；没有读取封存最终题。评分只在检索完成后使用，业务绑定与评分原文分开。原始结果、实际上下文、模型修订和配置见 `quality-return-evaluation/`。

| 开发实验 | 版本限定 | 版本限定＋分支投影 |
|---|---:|---:|
| 首次完整条款覆盖 | 9/20 | 9/20 |
| 首次出现其他分支片段 | 17/20 | 0/20 |
| 一次补检后完整覆盖 | 20/20 | 20/20 |
| 补检后出现其他分支片段 | 20/20 | 0/20 |

首次实验没有提高召回率。补检实验是看到该问题后、另写标准的同开发集探索，两臂都在24题中15题追加检索；不是预先独立验证。补检后的4条未知事实题均返回了政策，但仍不具备实际退款、到账或激活字段，不能据此回答。没有调用生成模型，因此这些数字不代表回答正确率或幻觉降低比例。

## 兼容与边界

迁移0009仅新增申请分支和质检缺陷字段，仍34张表；旧申请默认无理由，旧质检判定未知。普通无理由输入保留旧序列化形状以兼容幂等键；旧需质检预览可能因新增字段而要求重新核对，不能直接绕过摘要校验。升级前备份保留在D盘。

规则含义和分支绑定仍由管理员确认，程序不自动理解任意政策或证明原文语义完备。没有真实质检设备、照片识别、售后运费／退款结算，也没有新增付费模型验证。详见阶段报告及 `quality-return-checks.json`。
