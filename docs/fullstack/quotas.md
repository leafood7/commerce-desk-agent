## 默认约束

| 约束 | 默认值 | 含义 |
| --- | ---: | --- |
| 单账号待执行流程 | 16 | queued/running；等待补充、确认和审批不占位 |
| 全局待执行流程 | 128 | 所有商家的运行准入；不返回其他人的队列明细 |
| 每次活跃处理 | 120秒、10次工具尝试 | 原有上限保留 |
| 单流程累计工具预留尝试 | 40 | 失败与重试计入，恢复与重启不重置 |
| 单流程模型预留尝试 | 1 | 接入已有单次路由约束，没有增加模型轮数 |
| 单流程模型token额度 | 16384 | 预留加已报告用量，非金额预算 |
| 每次模型预留 | 8192 | 请求前占用；未知用量不释放 |

配置见.env.example的WORKBENCH_QUEUE_*与WORKBENCH_RUN_*。准入限制使用当前服务配置；流程累计上限在创建时保存快照，改变环境变量不会解锁既有流程。旧流程首次接入按历史轨迹保守导入并标记legacy_estimate，可能高估重试次数。

限制针对Agent运行，不包括文档上传/索引队列，也不是所有HTTP连接的限流。默认仍单个执行worker，不承诺持续吞吐、生产公平调度或多副本容量。

## 准入与取消

MySQL单独的admission门闩与运行受理同事务使用。先结束只读认证事务，再取门闩，之后建立一致性读；避免认证产生的旧RR快照让并发请求漏计。门闩无用户/组织外键，不要求worker取得它。进入受理函数前存在未提交新建/修改/删除对象时拒绝处理，防止提前提交其他业务变更。

满载返回HTTP429及Retry-After:2，不创建半份会话、消息、运行、作业或用量。相同幂等键优先返回既有流程；不同输入同键仍冲突。所有API进程必须使用一致配置和版本，未验证跨版本滚动升级。

取消在本地数据库直接终止，不必再排队；排队作业同步标为skipped。尚未提交的售后取消移除旧预览和未复核引用；已提交申请不会被谎称撤销，写入不确定时仍禁止直接取消。只读查询取消保留原有空output契约。

## 用量与人工核实

GET /api/v1/runs/{id}/usage 仅允许流程本人。新流程同事务初始化用量，工具调用前先持久预留，模型调用前预留、返回后结算。首次查询旧流程可能持久化保守估算；接口不接受重置或修改请求。

模型明确在网络请求前被预检拒绝时释放token预留，但该次预留尝试仍记账；超时、格式错误、缺失/矛盾用量保留预留。供应商报告超出预留/上限时如实记录并回退，不截断数字假装满足额度。UTF-8字节预检是保守近似，不是供应商精确tokenizer，也不能追回已经产生的用量。

cost_cny返回null，不将未知费用写成0。开发评测原100元账本仍独立存在，本功能没有替代跨流程、跨账号的人民币总预算控制；本轮没有调用真实模型。模型默认关闭。

GET /api/v1/runs/{id}/business-status 是本人流程的人工只读核实入口。服务端按组织、创建人、固定幂等绑定查询实际申请；不调用模型/MCP写工具、不占Agent工具额度、不重新办理、不修改流程状态。返回found或not_observed；未观察到不能解释为进行中的提交已撤销。界面按run_id绑定结果，避免切换流程后串用回执。
