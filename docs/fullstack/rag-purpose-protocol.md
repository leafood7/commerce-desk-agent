# 引用补全与分支投影：实现前标准 v1

本轮复用第11阶段768条已保存证据，不重新召回、不调用模型、不覆盖原结果。只选版本限定的邻居上下文和引用补全上下文，分别验证“原样保留”“无差别按申请分支投影”“明确任务目的后选择”三种策略。

业务映射来自合成政策的明确章节：无理由为第2／3／22条，质量问题为第2／4／12／16／20条。映射在运行前固定，与评分问题分开；投影仍只能抽取本次已召回原文，不补入未召回条款。不得把评分答案或复核结果放回召回。

32条原始问题均是没有办理指令和订单事实的规则／事实问句，固定标记policy_question。另复制第5／9／13／17／21／22／23／24题的实际证据，增加8个明确application任务变体，用来检验当前分支、更正和缺证据边界。这些是人工指定任务元数据，不是模型分类，不是新独立测试。

3档×2检索上下文×40任务×3策略，共720条离线策略结果。分别报告另一分支预标注原文出现、整套办理条款覆盖、空证据、5道已有人确认口径的最小问题证据命中、投影新增证据丢失。无差别投影只是对照，不启用。

生产程序目的由已有入口决定：knowledge_search和独立政策检索API为policy_question；退货Graph默认application，明确只读沿用现有受限识别。办理审批、金额、写入及未知事实逻辑不变。保持原投影函数兼容；问答原文返回不等于事实已知或结论已证实。任意自由混合问题的任务识别不在范围内。

必须覆盖空检索不补造、未知目的拒绝、问答不被申请映射删证据、办理不回退全文、用户更正使用当前映射、虚构来源和过期源不能发布，以及问答不建退货单。程序／实际HTTP MCP／适当MySQL与浏览器验证后才交付。默认检索范围和跨条款引用实验开关不自动改变。

关键风险：规则问答保留原文可能保留多分支，需核对语义；严格投影能隔离片段但无法提高召回，可能保持缺条款。只允许称为证据保留与潜在误拒风险验证，不能称为模型误拒率或线上准确率改善。
