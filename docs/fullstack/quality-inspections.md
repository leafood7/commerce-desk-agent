# 演示质检工单与退货 Agent

本阶段把上一阶段“没有可信质检字段”的边界，推进为“可以读取独立操作人登记的演示质检记录”。不是外部质检设备接入，不代表实际检测或真实平台结论。

## 业务契约

工单绑定当前商家、订单商品行、确切申请数量。状态为 `requested → in_progress → completed`；管理员可撤销为 `voided`。完成后的结果不能原地覆盖，更正需撤销或创建新工单，历史事件保留。只有最新工单可用，新工单待处理或旧结果撤销后，不回退使用历史通过记录。

客服创建工单，审批角色开始并登记结果；创建者不能处理自己的工单，开始处理的人才能完成。管理员只能执行撤销操作。写入带预期修订号，创建还要求幂等键；同键同参数返回同一记录，不同参数冲突。跨商家或订单商品不匹配返回不可访问。

`passed` 和 `failed` 是明确结果；`inconclusive` 仍需核实。政策可声明：

- `recorded`：要求明确结果，不能擅自添加“必须通过”。
- `passed`：管理员依据原文明确要求通过，未通过时阻止该演示规则申请。

质检要求可绑定 `quality_clause` 原文，并与其他政策证据一起校验、检索和展示。新界面登记需质检规则时必须选择该原文；兼容此前仅声明必需事实的规则。含义由管理员核对，程序只核对来源与字面引用，不声称自动理解政策。

## Agent 如何使用

MCP 只新增只读 `get_quality_inspection(order_number,item_id,quantity)`，不提供登记结果或批准工具。程序固定这些入参，模型不能提交自报结果。网关核对绑定、状态、修订、结果、来源和演示标记。

引导流程 `guided_v3` 在政策要求质检，或用户明确询问质检结果时查询；普通退货不额外查询。缺少要求的明确结果时暂停为 `quality_wait`，不创建退货申请；用户刷新后重新读取订单、质检、资格和政策。明确只读查询结束于结果说明，不进入申请。质检通过后仍须用户确认预览和独立退货审批。

质检记录及修订进入预览摘要。申请确认、批准和模拟受理都会重新检查；结果被撤销或被新工单取代时旧预览不能继续。已经完成的模拟受理不会因后续质检记录变化而被虚构为撤销。

## 本地演示步骤

1. 管理员发布规则模式的 `guided_v3` 配置，可选择政策版本收窄检索。
2. 使用新增演示订单；选择带质检要求的规则，明确未使用并启动 Agent。页面显示等待质检。
3. 客服点击“为当前商品及数量创建演示质检”，记下工单编号。
4. 换审批账号，在退货申请页选该工单，填写说明并开始处理，再登记演示结论。
5. 返回客服页点击“刷新质检结果并重新核对”。通过且满足其他规则后，才显示退货预览确认；确认后进入退货审批。
6. 管理员可用说明撤销该质检，重新验证旧预览和后续办理会被阻止。

规则下拉框会显示是否需要明确结果／通过，以区分同商品的两条演示分支。没有质检要求的规则继续原流程。

## 当前边界

尚无检测设备、仓库、质检供应商签名或照片自动判断；人员记录也不代表客观真实。商品仅按订单行及数量绑定，未做到单件序列号追踪或部分送检实物分配。处理人角色复用审批角色，没有另建组织级质检岗位。工单没有自动通知和 SLA。等待流程需显式刷新，并受原有调用与恢复上限约束。没有付费模型评测或线上效果结论。

后续适合深化的方向是质量问题退货分支：将“无理由退货”与“质量问题处理”的政策条件、凭证和流转分开，用同文档例外与更正样本验证 RAG；先确定领域规则，再决定是否需要模型辅助解析。
