# 按政策子问题协作

## 功能

在原有取证、回答、核验角色之外，增加服务端任务整理与证据协调。把当前政策问题整理为范围、期限、条件、例外、费用责任等事项，保留触发该事项的用户原话；不自动拆出与当前问题无关的整个办理清单。

流程：任务整理 → 取证 → 证据协调 → 必要时交回取证 → 回答 → 核验 → 可选的一次修订。任务整理和协调属于程序控制节点，不冒充额外的大模型。原来的三个模型职责继续保留。

## 使用

服务端已允许模型、按需原文阅读及核验回答时，管理员在配置版本中选择：

- 政策问答协作：取证、回答、核验协作。
- 协作执行方式：按政策子问题交接与补读。

保留原有顺序协作。新配置只影响新任务，已保存配置缺少新字段时仍按roles_v1执行。默认仍为单流程，不安装或自动启用真实模型密钥。

政策检索和退货只读政策咨询会展示“本题政策事项”，分别说明哪些事项取得资料、哪些还需补读、哪些没有找到。答案通过检查后，再显示逐项答复状态；未确认的事项不伪装成完成。会话记录中可重新查看公开的协作事项，不读取内部草稿。

## 交接和约束

取证仅使用获准的搜索/原文阅读工具。已发布的人工审核条款可以提供分类和原文位置，帮助定位当前问题所需片段；整理后的说明不会直接成为可引用证据，回答仍引用经过校验的原文。

回答的结构化草稿必须逐项列出task_answers，将每项关联到具体结论，或明确标为not_confirmed。程序拒绝遗漏项目、无效结论下标和把未确认事项伪装成全部确认；语义核验继续检查结论是否真的回答该项、范围条件是否正确。

多个期限只是需要核对分支的提示，不自动判为政策冲突。不同商家/地区/渠道的资料不能直接合并；缺政策不能靠询问无关商品状态补齐。

仍共用最多2次原文阅读、4000字符、1次补检和原有模型/token额度；协调最多3次取证交接，不增加一套新的预算。停止原因显示为没有更多获准来源、额度已用尽、交接轮数上限等。已完成读取按原缓存复用，不重发未知结果。审批、金额、资格与业务写入保持原业务规则控制。

新版使用knowledge_roles_v2私有SQL检查点；旧版仍使用knowledge_roles_v1。恢复时重新检查原文及审核条款的当前绑定，审核条款换版也会使旧交接失效。

## 边界

子问题整理与资料线索匹配是有明确范围的规则辅助机制，不能视为通用语义理解。找到片段、分类相符或模型批准，都不证明事实必然正确。模型核验及未知边界仍然必要。

本轮只做功能开发与必要的正常/失败路径自测，没有开展benchmark、单/多Agent优劣对比或真实模型效果评测。浏览器操作使用明确标注的本地模型替身，验证角色交接、工具和界面连接，不能作为真实模型回答质量的结论。
