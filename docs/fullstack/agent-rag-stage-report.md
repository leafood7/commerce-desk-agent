## 实现与意义

模型可在最多两个只读工具之间提出执行顺序，Pydantic 校验禁止额外参数、写工具、重复工具以及缺少必要查询。工具参数由可信业务状态构造；LangGraph 执行经过校验的计划，非法计划回退到固定查询。确认、审批、业务规则和幂等规则继续由服务端控制。新增 tool_plan_mode 可识别实际采用模型计划或回退。

增加可选章节上下文扩展：同版本、同组织、同章节附近片段在字符预算内组合，保留原始来源及锚点。默认仍使用 neighbors；不会把模型文字或历史回答当作证据。章节边界可能隔离必要例外，不能仅凭上下文变短就开启默认。

## 可复现材料

冻结输入在 data/evaluation/agent_rag_v1；入口 scripts/freeze_agent_rag_stage.py（禁止覆盖冻结文件）、scripts/evaluate_stage_model.py、scripts/evaluate_stage_long_rag.py。真实调用与原始返回、用量、清单在 work/agent-rag-v1/model 和 model-v2；RAG 原始轨迹与汇总在 work/agent-rag-v1/rag；总账 work/answer-trust/budget.json 不得重置。

已有请求正文是在调用后从已知输入及提示词逻辑重建，requests.json 明示 reconstructed_after_run；不能冒充当时完整抓包。后续脚本直接记录请求体但不记录密钥。原始回答未覆盖。source_hit 是从冻结来源映射及原始结果后处理的指标，原始轨迹保留。

离线复现需先安装锁定依赖、准备 D 盘模型缓存，再以 PYTHONPATH=src 运行 RAG 入口。真实模型入口会产生费用，须检查既有总账、阶段授权与预算预留；不应为重现报告无意义地再次付费。不要读取封存最终题集。

## 难点、学习与下一步

实际困难是模型语义判断可用但 JSON 层级不稳定：通过明确契约与示例改善，程序校验继续保留。另一难点是“上下文变短”容易被误读为“回答更正确”：保留覆盖、误召回和失败案例，拒绝只展示压缩数字。

如果由你独立实现，难点会是把模型建议与业务授权分开、理解 LangGraph 中断重入、保持来源版本隔离、设计公平对照和记录预算。建议先实现非法工具/参数必须被拒绝的测试，再接模型；先看逐题原文与失败，再调整检索。

下一步进入运行可靠性：限制每次活跃执行的工具次数与耗时，只对只读瞬时故障有限重试；写入保持稳定幂等键与真实回执；通过故障注入验证。之后再完善工作台配置、事件恢复及部署交付。服务器购买、破坏性数据操作须用户决定。
