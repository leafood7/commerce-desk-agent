# 政策提取、独立审核与发布

## 使用入口

工作台 → 知识库 → 找到已完成解析的退货政策 →「政策提取与审核」。未发布的新文档也可以先提取、审核，再发布。

1. 管理员点击「自动提取政策候选」。系统按范围、期限、条件、例外、费用与责任整理带原文定位的摘录。未识别项、不同期限及明确提及的条文会提示核对。
2. 管理员修改整理说明和分类，删除不合适的候选，或从完整来源片段补入遗漏条款，填写说明后提交独立审核。原自动候选仍可对照。
3. 审批员在同一入口核对候选和全文片段，填写意见，确认范围、例外、未知项及解析警告后批准，也可以驳回。
4. 管理员发布已审核政策。新文档的原文版本与审核条款一起发布；已有有效文档可以发布新的整理版本。只有已完成索引、有效且满足现有解析修订审核规则的文档才可发布。
5. 客服在政策检索的来源卡片点击「查看已审核条款」，查看整理说明与对应原文。撤回、换版、到期或来源变化后，旧整理不能继续作为当前有效内容读取。

驳回后重新提取会产生新候选，原审核记录保留。编辑和审核使用修订号，过期页面不能覆盖新状态。候选未审核时，原文发布接口也不能绕过审核发布该版本。

## 边界

第一版是规则辅助摘录，不调用外部大模型，不声称通用语义抽取。提示“未识别”不代表原文没有这项规定；不同期限提示也不直接判为冲突，必须对照各自适用范围。人工整理说明和原文引文分别显示，不将整理后的表述伪装成原文。

候选与审核历史持久化在MySQL的新表wb_policy_extractions。人工修改的前后内容进入既有审计记录。文档原件、解析快照与既有索引继续保留；增加的是政策整理工作流，不重写原文件。

发布审核条款不会自动创建ReturnPolicy，不决定订单资格、退款金额或审批结果。用于办理的可执行规则仍须走原有管理员明确配置与业务校验。自动语义提取、知识更新影响分析及多Agent进一步消费审核条款属于后续功能。

## 运行与维护

数据库需执行现有迁移命令至0010_policy_extractions；这是增加候选表的迁移，不删除已有表或业务记录。生产式操作前保留数据库快照。降级若存在审核记录将拒绝删除表。

常用接口：

- POST /api/v1/knowledge/versions/{version_id}/policy-extractions：生成或恢复当前候选。
- GET /api/v1/knowledge/versions/{version_id}/policy-extractions：管理员/审批员查看候选历史。
- GET /api/v1/knowledge/policy-extractions/{id}：候选详情、原文片段及来源变化状态。
- POST .../{id}/save、submit、review、publish：编辑、提交、独立审核、发布。
- GET /api/v1/knowledge/versions/{version_id}/policy-summary：当前有效的已发布整理，客服可读。

单份政策最多200个片段、20万字符、100条候选；超出时明确要求拆成可审核文档，不静默截断并假装提取完整。候选不能跨组织读取；客服不能提取或审核；提交者和最后编辑者不能审核自己的候选。

本功能没有启动benchmark、对比实验或真实模型效果评测。功能自测覆盖正常操作、权限、来源变化和发布控制；后续效果评测须另行确认。
