# 最多一次回答修复实验

## 实现

新增reviewed_repair模式：初稿经程序和语义检查后，仅在本轮证据没有已知缺口时最多修复一次，再经完整程序与语义检查；不追加检索、不调用业务工具。无效引用、缺失工具字段、非JSON结构不自动修复。明确任务约束错误（例如规则咨询多余办理清单）可在引用和字段已合法的前提下进入修复；不对无效原稿浪费语义检查。

修复尝试在模型调用前持久占用，恢复不清零；每一阶段有私有缓存和共享调用/token额度，未知用量仍预留。修复失败、二次检查失败、超时、取消或额度不足保守停止，不循环。修复结果不能审批、退款或改变资格规则。旧contract/reviewed模式不自动修复，默认模式未改。

## 验收

15项注入测试通过，覆盖三模式差异、直接通过、语义修复成功、程序约束修复、伪造引用不修复、修复新增无效引用、再次审查失败、超时、缺证据、额度不足、取消、缓存恢复和最多一次标记、公开接口/SSE/历史隔离、服务端未授权不能启用。它们使用明确的模型替身，证明机制，不证明自然模型准确率。较广105通过2跳过，均有重叠不相加。前端构建通过，实际浏览器1项通过：可见修复和再次核验进度；成功与失败均没有泄露原稿/修复稿，无无限重试。

## 自然三模式验证

3条新编开发问题，每题复用同一文档版本、演示订单和检索配置，交替contract/reviewed/reviewed_repair顺序，共9流程。三模式程序目标均3/3，但没有自然修复触发，不能宣称修复提高正确率或解决率。原始回答仍需人工关键复核；模型approved、结构合法与回答正确分别判断。即使全部流程走完，也不写100%准确。

本批实际18请求，保守0.047944元；原授权累计84/128请求、0.235794/1元，100元账本累计4.992324元，未知0。只发送新编演示政策/问题和隔离字段，密钥仅标准输入，不落环境、SQL或证据。单次修复实际多出多少调用据真实阶段记录计算，不把上限当已消耗，也不把注入模型用量当真实账单。

阶段3的6家族保留为回归，没有重放已付费失败案例；本批新开发题不称外部独立盲审。当前只交付实验机制，缺少自然修复净收益证据，因此不默认启用。源码快照、冻结清单、原始轨迹及失败记录保存。本轮未commit/push，日常容器尚未更新，源码走读继续暂停。
