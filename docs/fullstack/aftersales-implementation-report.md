## 本轮交付

已跑通：用户提出催单/加急需求 → 缺信息暂停 → 查询实际订单和已发布政策 → 核对业务条件 → 用户确认 → MCP幂等登记申请 → 加急等待独立审批 → 查询真实申请/工单状态。前端提供售后助手、已有流程恢复、实时步骤和独立审批面板。

这是围绕普通催单和加急申请的受约束LangGraph工作流。使用真实StateGraph、interrupt、Command恢复和MySQL检查点；不是用前端变量假装暂停。退款、退货办理、赔偿和外部仓库通知尚未接入，结果不会虚报这些操作完成。

## 关键实现

- 新增0003_aftersales迁移，保存图检查点、中间写入和幂等恢复记录。私人图状态与公开回复分开，登录/工具凭据不进入检查点。
- 每次补充、更正、确认或刷新都校验运行所有者、组织、当前暂停标识和动作。确认请求不能夹带新的订单或原因；前端修改后必须重新核对。
- 写入前重新查询订单、核对条件和证据。并发确认只受理一次；用户等待期间订单已发货或承诺时间缺失，不继续登记加急。
- 写工具固定使用运行级幂等键。提交过程中不把取消显示为“没有执行”；响应超时但业务可能已提交时，恢复核实既有申请，避免重复办理。
- 审批员独立操作，客服或模型不能在图里自行批准。流程结束、申请获批、工单创建、外部通知是分别展示的状态。
- 办理后旧政策引用变更，移除失效引用并提示，但不隐藏已经发生的真实业务结果。
- 普通查单直接展示字段；知识问题保留原文与证据边界；未接入的业务明确说明能力限制。

## 大模型接入到什么程度

默认规则路由，不执行付费模型调用。本轮额外接通了可选的一次OpenAI兼容模型意图分类：严格限定四种意图、256输出token、10秒超时、无自动重试；SQL在调用前预留，崩溃恢复不会再次调用分类器。失败或格式异常回到规则路由，不扩大工具权限。

模型不能生成审批结论、自由修改工具参数或跳过确认。真实模型意图分类质量尚未评测；本轮通过替身验证协议和失败处理。自然语言政策答案生成、通用多工具ReAct、上下文压缩和全局模型费用熔断尚未完成，不能据本轮验收宣称已经具备。
