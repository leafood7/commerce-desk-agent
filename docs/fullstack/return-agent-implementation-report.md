# 从固定退货图到受限模型决策：实施与开发对照

日期：2026-10-29。开发基线：`1e8f369`。代码位置：`D:\VScodeProgects\commerce-desk-agent`。本阶段围绕已有退货业务深化Agent和RAG，没有增加业务模块、部署组件或真实退款能力。

## 交付与边界

新增观察驱动的LangGraph读/问循环。模型可以根据真实工具返回，提出查询、条件检查、一次补检或询问商品状态；只接受当前合法动作集合中的单个动作，不接受自由工具参数或业务结论。确认、审批、金额和写入沿用原领域服务。非法输出、超时、额度不足与未知结果均有规则回退。

同时增加可独立选择的政策版本收窄。版本来自商家已登记的政策绑定，查询仍受组织、发布和有效期限制；不能把某个文档ID当作新的授权。模型开关、检索开关、提示SHA与已有配置/检查点兼容机制接通，前端可看实际动作及规则回退。

默认继续规则决策与基线检索，真实评测没有启用日常付费运行。旧配置缺少新图标记时保留原图。操作见 [return-agent.md](return-agent.md)。

## 先冻结再实验

[标准](return-agent-stage-protocol.md)与 `data/evaluation/return_agent_v1/` 在候选实现前建立，带SHA校验。24个作者编写的开发问题按6个政策家族组织：普通实物、电子商品、定制商品、会员延长、运费券、退款状态。相关改写留在同一家族；全部为开发材料，没有读取原封存最终题。

真实模型的8类离散观察先冻结；随后3类完整链路属于实现后的集成验证，不是独立语义盲测。评分自动执行，人工最终语义复核尚未完成；不宣称独立评审或线上客服准确率。

改善来自两题：`return-dev-003`补齐“超过无理由窗口仍需人工核对质量问题”的例外；`return-dev-023`补齐“模拟受理不等于真实退款”的能力与状态边界。24题中没有观察到必要条款覆盖下降。

上下文字符减少约24.36%，不是token或费用减少的证明；耗时是本机小语料单轮交替观测，不是生产性能承诺。零“其他政策文档比例”也不代表同一文档内每个条款都适用，运费券文档仍含用于区分的商品券说明。

六个无依据问题仍有相关文本，不能由此生成所问的真实金额、激活时间或银行入账事实；检索片段出现也不直接等同错误回答。本轮没有生成并人工评分这些自由回答，因此不报告语义正确率或误拒答率改善。政策绑定为人工设定的业务上下文，不是系统自动推断适用政策的成绩。

## 真实模型：完整链路可运行，尚无默认启用依据

获得用户对DeepSeek官方目的地及隔离演示字段的明确授权后，执行24次请求：8类合同观察各1次，3类模型链路分别4/6/6次。没有失败或未知用量；24个建议均为合法动作。这里不少状态只有一个合法动作，合法率受程序约束，不能称模型判断准确率。

| 链路 | 规则路径在办理前的结果 | 模型路径在办理前的结果 | 真实模型请求 |
| --- | --- | --- | ---: |
| 正常未使用商品 | 等待用户确认 | 等待用户确认 | 4 |
| 未知商品状态→补充未使用 | 等待用户确认 | 等待用户确认 | 6 |
| 更正为已使用 | 说明限制，未建单 | 说明限制，未建单 | 6 |

两条可申请的模型链路随后完成用户确认、独立审批和模拟受理；规则对照在办理前停止，不拿“仅模型继续办理”制造完成率优势。隔离链路使用真实HTTP MCP、真实本地向量/重排、数据库与持久图；API入口用TestClient，向量库用隔离持久客户端，不能称整个环节都部署成独立服务器。

相同办理前阶段的工具次数均为3/6/6，模型没有减少工具。补问链路观察到约3.86s→10.91s，更正链路约4.16s→11.75s；正常链路规则首轮包含冷加载，约12.04s→8.18s，不能将其宣传为模型更快。三个相关开发场景也不足以证明任务完成不下降的一般结论。

因此保留规则默认。下一步更值得验证的是只在真正有歧义、自由表达或多意图时使用模型；当前循环中强制单动作阶段的调用属于已识别冗余。不得为了展示Agent而让标准查单或简单退货反复询问模型。

请求温度0、关闭思考、最多256输出token、不自动重试；返回模型字段为 `deepseek-flash` 别名，不是已锁定供应商权重版本。按本轮核对的[官方峰值单价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)（输入2元、输出8元/百万token）保守估算0.019846元；累计总账4.566046元，不是账单。阶段24次上限已用完，脚本拒绝追加；5元授权池包含此前调用，没有另起账本。
