# 退货Agent按需搜索、阅读与询问：阶段3工程交付

日期：2026-11-01。范围为现有guided_v3订单行级退货流程，不是全站通用研究Agent。未读取封存最终题，未发起真实模型调用，未提交或推送。

## 业务变化

旧流程发现必要来源缺失时只能补检一次；同样的检索仍未找到时就结束。现在增加一个选择：读取命中章节的原文或明确关联章节，再根据真实结果继续核对。读齐政策后仍缺商品状态，就询问；缺实际签收、缺陷或质检结论，仍使用现有业务工具和核实流程，不从政策猜事实。申请预览、审批、金额与受理仍由确定性代码控制。

## 实现程度

- 在现有LangGraph观察—决策循环中加入read_source动作，保留规则基线和受限模型建议。模型仅可返回合法动作及服务器目标编号，不可传文件路径、版本、偏移、自由工具参数或办理指令。
- 阅读位置来自经过校验的检索章节和工具返回的同版本明确关联条款；长章只能继续读工具提供的下一页。已有完整父章节时跳过重复阅读。
- 每次运行最多补检1次、原文阅读2次，单次2000字符，累计4000字符；所有调用共享已有工具、模型与时间上限。条件变化后的首次重新检索属于新条件核对，不重置补检和阅读累计额度。
- 阅读和补检额度调用前存入私有数据库记录，检查点丢失不能恢复已消费额度。原文读取不自动重试。用户更正时清除旧证据、旧目标和本轮去重记录，但保留整个运行的额度与历史。
- 原文窗口重新按当前组织、有效版本、来源哈希、章节及偏移组装，发布前再次核对。只将窗口中完整包含的真实片段标为覆盖；不把读过部分章节算作读完整份政策。表格重构等不能逐字匹配的情况保守保留缺口。
- 区分整个申请的必要来源和当前问题的来源：只查真实字段不靠读政策补事实；同时问政策和事实时保留政策补读需求。第一版问题识别使用明确的业务词规则和管理员已核对条款，不声称任意自然语言理解或自动法律解释。
- 工作台增加原文补查记录，显示调用次数、字符数、章节、是否还有后文和失败情况；公开只展示结构化动作与实际结果，不展示模型自由草稿或隐藏思维过程。

## 怎么启用

默认关闭。服务端设置WORKBENCH_RETURN_SOURCE_READING_ENABLED=true；管理员发布guided_v3、clause_bound、return_source_reading=true的配置。决策可先保留rules，无需模型费用；只有原有服务端模型开关和授权都具备时才考虑model。Compose和.env.example已接入开关，普通管理员不能绕过服务端限制。

原文阅读依赖parent_child入库的定位信息。历史结构化政策仍可走原路径；没有定位的旧政策不伪造可读位置，需要在后续维护中作为新版本重新入库。纯政策检索页仍是普通检索/问答入口，本轮主动阅读接入退货Agent，没有把每个问答强制改成Agent。

## 验收与实际效果

1. 较广回归95项通过，315.15秒，覆盖退货图、受限决策、引导流程、RAG范围、父子原文、回答发布门禁和配置。最后补齐混合问题要求后，专项18项通过，65.50秒。两批重叠，不相加。
2. 专项涵盖缺条款后阅读、跨章明确关联、充足证据零阅读、非法目标与越权动作拒绝、原文篡改及撤回拒绝、两次分页上限、失败不自动重试、更正不重置额度、模型合法选择/非法选择回退，以及检查点之外的持久额度上限。
3. 同一人工缺口样例对照：原路径检索2次后仍不完整并结束；开启后检索1次、阅读1次补齐来源，进入待确认预览。模型、向量检索在该单因素回归中是显式替身，使用实际HTTP MCP与持久图；它只说明这一缺口可通过阅读解决，不代表真实模型准确率。
4. 浏览器完整流程1项通过，约9.97秒：实际MySQL、BGE、Chroma、重排、HTTP MCP与LangGraph。隔离演示政策人为增加背景段落，并收紧检索窗口，使必要条件无法一次装入。读原文后停下来询问使用状态；补充后重新核对进入预览。两次阅读共1316字符，模型调用0、未创建退货申请、未执行退款。
5. 浏览器第一轮标签定位过严，修正了脚本；随后原始短政策已召回全部必要条款，系统正确零阅读，但预设“必须读一次”的断言失败。保留记录，改用确有缺口的长章演示再验收，没有为凑阅读次数修改系统。另一次隔离准备因上传端和工作线程存储路径不一致失败，统一路径后入库成功。
6. Python静态检查、TypeScript/Vite构建和Docker构建通过。本地四后端服务各61源码与当前文件一致；默认rules/excerpts、阅读关闭、无真实模型密钥，数据库34表，原有3条申请保留。

## 限制与下一步

本轮完成退货垂直场景的有界搜索/阅读/询问工程能力，不代表整条路线所有阶段完成。没有新真实模型决策或回答语义实验；此前语义审查漏检的两项问题也没有被本轮结果宣称解决。因此新能力保留实验开关，不宣传线上准确率或客服降本。

下一步优先解决真实业务发现的知识维护缺口：把来源定位、解析修订、新版本审核和索引/FAQ失效连起来；同时为本轮阅读决策准备更独立的任务对照，比较该读未读、不必要阅读和误补问。付费模型验证另需授权，源码走读继续暂停。不扩展新业务模块，不堆多Agent或无业务职责组件。
