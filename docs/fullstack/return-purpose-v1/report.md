# 退货任务目的与政策复用修复

## 本次解决什么

把明确的规则咨询、实际字段查询和退货办理分开。规则咨询通过新增只读MCP工具get_return_policy核对本商家当前发布的映射，无需订单、商品行、数量、原因和使用状态；不调用资格检查或创建申请。任务判断保留用户原话及位置，是保守规则路由，不宣称通用语义理解。模糊表达仍保留旧入口行为，后续应验证显式目的选择与澄清。

实际字段查询走真实订单或质检工具；工具不具备的到账/退款等字段直接说明未知，不为这些字段继续读政策，不调用生成模型。回答与公开订单字段只展示所问字段；质检查询只索取订单、商品行、数量。正常办理仍经条件核实、预览、确认、独立审批及模拟受理。

数量或使用状态更正后，订单与质检重新查询；已有实际检索/阅读的政策按当前版本、范围及政策绑定重新校验，成功才复用。旧助手文字不复用。阅读/补检额度仍累计最多2次/4000字符/1次，不因更正恢复。已读窗口不重复读，阅读围绕服务端确认的命中位置安排；补检聚焦仍缺的映射条款。来源撤回后移除旧引用和旧预览，保留真实办理记录。

## 长输入怎么处理

仅去掉被同版本原文窗口完整覆盖的重复子块。模型输入把相同版本、范围、章节元数据合并，完整政策文字和引用ID保留；输出Schema只删展示标题、保留校验约束。精简重复提示语，不扩大6000输入上限。旧失败输入离线复验：journey-013从原记录6942到最终5754；014从6764到5731，均为保守UTF-8字节上界，不是提供商实际token数。不是丢弃例外来凑预算，真正超限仍保守停止。证据组装范围或原文不完整仍单列，不能因引用存在宣称充分。
