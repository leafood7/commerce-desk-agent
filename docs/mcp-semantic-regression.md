# 真实 MCP 回归：语义边界与工具执行

版本：`e1067a8`；运行日期：2026-10-22。验证范围为真实模型、LangGraph、生产 MCP Server 与业务查询，不包含 HTTP API、浏览器点击或并发压测。

## 解决的问题

优惠券回答需要区分三类输入：

| 输入 | 处理方式 |
| --- | --- |
| 券面明确写“仅限食品” | 根据品类限制直接判断，不重复确认已知条件 |
| 用户只说“食品券” | 给出带券面范围前提的结论 |
| 只知道“食品节券”活动名 | 不推断品类限制，检索一般规则并核实券面范围 |

检索没有支持证据时，回答仅说明无法确认、请求必要信息，不在“待核实条件”里补写假设性政策。物流回答也改为“记录显示运输中”，避免将系统记录当作实际签收状态的保证。

真实回归还暴露了一处校验问题：检查器复用有效片段时可能返回空查询，原程序却要求填写新查询，导致多余回退。现在 `reuse` 允许空查询，但必须引用已返回的有效 ID；无效 ID 且无查询仍拒绝。检查响应的校验失败也保留已返回的 usage。

实现位于 `src/agents/answer_policy.py`、`policy_evidence.py` 和 `supportpilot_agent.py`。

## 方法

运行原18条合成对话，共23轮。每题使用独立内存会话，逐题顺序执行，检查模式为 `auto`。订单来自临时虚构库，政策索引使用隔离副本，催单写工具被阻断。

接口为 `https://api.deepseek.com/v1`，配置模型为 `deepseek-chat`，回答响应报告的模型名为 `deepseek-flash`。脚本保留源码哈希、每轮回答、工具结果、MCP 轨迹、usage 和耗时。

程序核对调用完成、MCP 路径、引用来源存在性、复用 ID 与写入边界；语义结论采用 AI 辅助逐题复核，尚未独立人工盲审。18题已用于调试，结果作为回归记录，不估计线上业务准确率。

本批轨迹检查均通过，逐题复核未发现重大结论错误。手机开箱题仍有多余查单邀请，保留为措辞改进项。107项离线测试及待提交快照测试通过。

固定历史查询“食品节券是否适用于键盘等非食品品类”的补测，实际返回 `no_evidence`，模型回答“知识库暂无依据，无法确认这张券能否用于键盘”，随后建议查看券面范围，没有补造条件政策。该补测单列1次检查、1次回答、1次检索，2,575 tokens，5.84秒。

修复前的自由查询已在本次运行中找到条款，固定空查询对照也正确拒答。因此，历史失败本次未稳定复现，不能据此计算一个前后准确率提升。明确品类限制的对照则从重复确认改善为直接判断。各轮问题和原始结果见[迭代记录](history/2026-10-22-mcp-iterations.md)。

## 逐案记录

| 案例 | 复核说明 |
| --- | --- |
| `known-phone` | 合理开箱不当然失去资格；列出激活、完好及期限。仍有多余查单邀请，但明确无法查询激活与实物完好，未承诺缺失字段。 |
| `known-gold` | 第二轮按金卡与未标注条件判断不适用15天，复用真实ID。 |
| `known-coupon` | 更正有效期后重新检索，食品券简称给带券面限制前提的结论，不沿用过期。 |
| `new-category` | 明确仅限食品即直接排除电脑主机，不再追问是否只是活动名称。 |
| `new-name` | 不把活动名称当品类事实，依真实一般条款给条件结论，仍要求券面范围。 |
| `new-store` | 店铺限定不能因同品牌跨店使用。 |
| `new-return` | 七天内不保证一定能退，保留激活、完好与购买提示条件。 |
| `new-fee` | 费用未收录，不编造金额。 |
| `new-quantity` | 真实空结果后拒绝编造固定券数。 |
| `new-activation` | 明确订单工具没有激活/实物完好字段。 |
| `new-signed` | 真实查单，表述为记录显示运输中；未将预计送达当签收时间。 |
| `new-mixed` | 同轮经MCP检索退款政策并查单，3至7工作日有来源；未误走纯订单快捷路径。 |
| `new-greeting` | 独立问候省检查，无工具调用。 |
| `new-thanks` | 独立致谢省检查，无工具调用。 |
| `new-order` | 真实MCP查单，商品/支付/物流/预计送达与虚构库一致，无催单写入。 |
| `new-repeat` | 第二轮reuse，引用历史真实片段，不新增检索。 |
| `new-correction` | 更正后按甲店券不能跨乙店处理，不延续过期。 |
| `new-after-thanks` | 首轮7天规则有依据，末轮致谢不重复查询。 |

## 复现

在项目根目录完成[环境配置](../LOCAL_SUPPORTPILOT.md)后运行：

```powershell
.venv/Scripts/python.exe scripts/evaluate_mcp_semantics.py --online --output work/my-mcp-regression.json
.venv/Scripts/python.exe scripts/evaluate_mcp_semantics.py --online --ids new-name --force-query "食品节券是否适用于键盘等非食品品类" --output work/my-mcp-empty.json
```

`--online` 会将合成对话、演示政策和虚构订单发送到配置接口，产生用量。`--force-query` 只控制检查器查询，工具检索和回答仍为真实调用；该实验与自由查询结果分开统计。输出存在时脚本拒绝覆盖。修复前源码与 manifest 位于 `data/evaluation/baselines/mcp_semantics/`。
