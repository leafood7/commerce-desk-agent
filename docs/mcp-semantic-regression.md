# 语义边界修复与真实 MCP 回归

2026-10-22。已实现并完成真实模型验证；不新增模型节点，不调整检索阈值或扩大TopK。

## 改动与价值

- 查询表达：先表达一般优惠券适用范围问题，保留已知条件；活动名不能改写为已确认的品类限制。
- 回答约束：明确“仅限食品”直接应用；“食品券”简称和“食品节券”活动名保留范围未知的前提。有一般证据才给条件政策；无证据时，不能在“待核实”部分补造规则。
- 物流记录：表述为记录显示运输中，不把记录当现实签收状态的保证。
- 真实回归发现并修复：reuse只需要有效真实证据ID，不应强迫填写不会执行的新查询；无效ID且无查询仍拒绝。检查输出校验失败也记录已返回的模型usage，不漏记已发生调用。

核心改动位于 src/agents/answer_policy.py、policy_evidence.py、supportpilot_agent.py。新增 scripts/evaluate_mcp_semantics.py，使用真实模型、生产MCPSupportPilotAgent与MCP Server；原生协议验证脚本继续保留。

## 对照与复现事实

修复前两题真实MCP对照保存在 mcp-semantic-before.json：new-category回答仍把明确限制写成假设并重复确认；最终已改为直接不能抵扣。new-name本次修复前已找到条款并正确回答，不能宣称该题从失败稳定提升为成功。

历史失败查询固定为“食品节券是否适用于键盘等非食品品类”，通过 --force-query 覆盖检查器查询以控制检索输入，实际MCP检索与回答模型保持真实；这与自由查询回归分开报告。固定查询修复前、修复后均实际返回no_evidence，本次两者都没有复现历史条件句补造。最终回答：

> 知识库暂无依据，无法确认这张券能否用于键盘。

随后仅解释活动名称无法确定范围，并建议查看券面或人工核实，没有补写“如果限食品就不能买键盘”的无证据政策。历史失败仍保留在旧报告，不改写原始成绩。
