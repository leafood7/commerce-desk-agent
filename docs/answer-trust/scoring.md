# 人工评分卡 v1

题集在实现前冻结：48个合成场景，开发24、留出24；每类每组4例。family 是核心条件/决策组合，跨组不得相同；同一政策文件可能支撑不同family，不能声称政策文档也未见。开发期间只使用dev；holdout不得用于提示或规则修订。编题者熟悉项目，留出并非独立真实客服分布。

## 逐场景评分

盲评者只看匿名版本、问题、完整回答、每轮实际证据及工具结果和预先评分卡，不看版本名称、成本或另组评分。不得根据关键词自动判为语义通过。

- major_errors：从categories.json六类选择实际发生的重大错误；同一场景同类最多记一次，保留对应断言、原文及理由。主结论之外的额外断言同样计分。
- completion：0=未解决且未提出有效必要澄清/转人工；1=仅部分完成；2=完成有依据的回答或卡片要求的必要澄清/有边界转人工。无必要拒答不算完成。
- citation_valid：yes/no/not_applicable。来源真实且本轮获准只是机械条件；还需人工判断是否支持对应断言。需要政策依据而未给来源应记no。
- reviewer_id、reviewed_at、rationale 必填；status只有pending/reviewed。禁止程序填入人工reviewed或伪造复核。

每条卡的required_points与prohibited_claims是评分提示，非唯一标准答案；若发现等价证据或标注争议，保留原评分和争议记录，不原地修改冻结题集。用户可以对有依据的争议记录独立裁决。

## 升级门槛

必须完整覆盖冻结留出集、基线与候选的固定证据层和MCP层，人工评分全部完成；只基于同一层/重复号的配对场景比较。两个层分别满足：有重大错误的场景数严格下降，completion总分不下降，各类重大错误场景数不增加，且没有新增非预期业务写入。报告成本与用量完整性；缺失用量或未完成运行不能当成零。若任何条件不满足，默认不升级；没有足够差异可结论为证据不足。

首次揭盲后如果据结果修订，holdout转为已知回归集，需要新版本新题再作晋级证明。报告只能声称冻结合成场景的结果，不宣称线上准确率或统计显著性。
