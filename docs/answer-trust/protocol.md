# 回答可信度实验：预注册协议 v1

本协议在新增回答机制实现前登记。基线为 `571af81e15696fc278e555e39d8694ca4a051572`，原有公开题全部视为开发／回归资料。未完成人工确认之前，新增机制默认关闭。

## 目标与假设

验证本轮证据隔离、结构化回答与一次语义检查能否减少关键错误，同时维持任务完成度。引用 ID 存在只证明来源有效，不证明结论受支持。不能依靠增加拒答获得质量提升结论。

三个版本：`off`（冻结基线）、`contract`（本轮证据、回答契约、程序校验）、`guarded`（contract 加一次语义检查）。最终生成直接输出结构；不增加格式转换调用。guarded 正常路径最多增加一次逻辑模型调用；失败后不修复、不复审、不追加检索。传输重试和失败用量单独记录。

## 数据与盲测边界

48条新场景分为24条开发、24条最终测试。六类各4条／组：语义强化（条件与例外）、适用范围、无证据断言、工具能力越界、引用有效性、多轮事实更新。同一场景家族及其改写不能跨组。

出题步骤只依据政策、工具契约和错误分类，不使用候选输出构造最终题。实现步骤只查看开发题；最终题由出题步骤冻结并记录哈希。候选源码和生成配置冻结之后才允许最终在线测试。若看过最终输出后修改系统，本批最终题即转为回归资料，需要新测试批次，不能继续称为未见测试。

题目是合成资料，出题步骤熟悉政策；不代表真实客服分布。人工复核者参与项目设计，因此只能称为“作者匿名复核”，不能称为独立盲审。

## 对照方法

固定证据层：各版本使用相同政策片段、用户条件和工具结果，测量回答机制。完整流程层：真实模型、LangGraph与MCP，保持相同初始订单及政策；写工具使用演示数据或禁止写入的替身，并明确标注。两层结果不能混合计算。

固定同一模型、接口、温度、输出上限、政策哈希和检索配置；版本顺序按场景轮换，重复运行显式编号。基线必须来自冻结源码，不能仅将当前实现标记为基线。保留原始答案、工具调用与返回、检查结果、错误、耗时、模型用量及缺失用量。

## 判分与启用条件

每个场景分别记录关键错误、任务完成、误拒答、引用有效性、条件遗漏；程序检查与人工语义判定分列。自动裁判仅辅助定位，不得填充人工评分。

匿名A/B/C材料隐藏版本与成本，保留可审阅的政策原文和真实工具字段。人工确认前显示“待复核”。只有最终集的人工复核完整、guarded关键错误少于off、任务完成数不少于off，并且程序约束／输出隔离测试全部通过，才允许提出将guarded设为默认。未满足条件时保留实验开关，不宣称已提升质量。

## 预算与停止规则

本阶段真实模型总预算100元人民币。先测量少量开发题，按已核实单价估算完整批次并保留失败余量；若超预算，正式在线规模在揭盲前缩为24条（12开发／12最终，六类各2条／组），将选择ID写入批次清单。仍超过预算则停止付费批次，交付离线结果和缺失项。

每次调用前预留输入和最大输出费用，不能仅在完成后检查预算。失败请求用量未知时保留预留，不当作零。不得在不同运行目录重置累计预算来继续消耗。超时、无效返回、模型服务错误都计入结果；不隐式重试。

## 输出边界与必测场景

内部草稿、审查提示和未批准答案不进入公开消息。工具进度可即时显示；最终答案完成检查后发布。SSE、普通调用、历史和AG-UI均须验证隔离。拒绝答案不能抹去已经发生的催单／审批状态。

必须测试：虚构与过期引用、未批准的历史证据、用户更正、订单缺字段、空检索、审查超时／格式异常／拒绝、工具调用混带正文，以及公有输出不含私有探针文本。审批与业务写入规则保持原有边界。
