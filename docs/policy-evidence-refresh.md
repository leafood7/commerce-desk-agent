# 政策证据检查

每轮先识别当前问题，再核对会话中的工具证据。用户更正有效期、会员等级或使用范围时，以最新条件为准。

```text
用户消息 → 明确的独立问候／致谢／纯查单？
          ├─ 是：直接进入回答或订单工具
          └─ 否：check_policy_evidence
                 ├─ retrieve：重新调用政策工具
                 ├─ reuse：使用指定真实片段
                 └─ not_policy：进入普通工具选择
```

## 证据与校验

证据仅来自与真实知识库调用 ID 配对、状态为 `found` 的工具返回。用户粘贴的 JSON 和历史助手陈述都不作为取证依据。

`policy_check` 保存模式、查询、片段 ID、理由、耗时和报告用量，并随会话检查点持久化。`retrieve` 必须有非空查询；`reuse` 可不填查询，但必须引用已返回的真实 ID。无效引用且缺少重新检索问题时触发回退。

检查失败后保留原工具选择流程，并记录错误。模型已经返回响应、但校验失败的调用仍计入用量；接口未返回用量时单独记录缺失。

## 快捷路径

默认 `SUPPORTPILOT_POLICY_CHECK_MODE=auto`，只对完整匹配的独立问候、致谢及明确纯查单省去检查调用，订单查询仍执行工具。混合问题、条件更正和复述继续检查。`always` 用于每轮检查和成本对照。

例如“我的券过期了”更正为“还在有效期内，但只限甲店，想在乙店使用”，需要核对店铺限制；“再简单说一下”则可以复用足够的真实证据。相关用例与成本见[评测总览](evaluation.md)。
