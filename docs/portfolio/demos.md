# 三段可复现演示

建议8—12分钟。只使用演示账号、订单及政策，不调用真实模型，不执行真实退款。“错误约束”演示指确定性条件阻止不适用办理，不冒充模型草稿后审演示。

## 准备和自动复演

先按 [运行说明](operations.md) 启动已有本地验收服务，再运行：

```powershell
cd D:\VScodeProgects\commerce-desk-agent
$env:PYTHONUTF8='1'
.venv\Scripts\python.exe scripts/run_portfolio_demo.py
```

命令增加一组带DEMO标记的新订单与政策，复用现有3条浏览器测试，0自动重试。运行前检查服务端模型关闭，不依赖测试进程的假模型变量。结果和结束截图先保存在私有 `work/portfolio/<时间_标识>/`，网络trace与视频关闭；不自动公开截图。

手动演示前使用 `--prepare-only` 生成另一组新订单，避免重复演示消耗同一商品的申请数量。新ID在 `work/returns-v1/demo.json`：`orders.normal`、`orders.quality_window`、`policy_id`、`defect_policy_id`。旧指针副本保留在本次目录，不修改旧订单。

管理员在“配置版本”记录原版本，创建并发布：规则模型、规则退货决策、新版原话澄清流程guided_v3、当前分支已召回原文组装clause_bound。发布只影响新运行，已有流程保留快照。结束后重新发布原版本。自动复演中的专项测试会自行发布/恢复所需配置；正常办理测试使用原配置，不能把整批宣称为模型路径。

准确的页面选项为“退货流程：原话确认与事实边界核对”和“退货政策范围：按当前分支组装已召回且核对的原文（实验）”。自动事实不足用例使用guided_v3＋policy_scoped，分支更正用例使用guided_v3＋clause_bound；手动说明使用后一种配置统一展示，两者不要混报成同一固定配置实验。

两个浏览器窗口分别登录客服support和审批员approver，禁止同一个客服替自己批准。页面地址 `http://127.0.0.1:15173`；商家demo-a，邮箱 `<角色>@demo.test`。容器密码来自私有 `work/docker/acceptance.env`，不要放进截图或讲解材料。

## 演示一：正常问题仍能完整办理（约4分钟）

规则列表只显示已加载规则中当前商品匹配的规则，不自动替你选择；更换订单或商品后须重新选择规则。

1. 客服进入“退货申请”，读取`orders.normal.number`，选择对应商品行与`policy_id`，数量1，商品状态“尚未核实”，填写退货原因，需求使用“申请退货，请核对适用商品、实际签收后的时间窗口和未使用条件。”
2. 启动核对，展示实际工具步骤和“请核实商品是否使用”。选择“用户确认未使用”，点击“补充退货条件”，得到预览。
3. 修改退货原因，展示旧确认按钮失效；点击“按当前信息重新核对”。记录当前流程ID，刷新页面并从“恢复退货流程”选回原流程。
4. 确认预览，仅提交独立审批。审批员按本次订单找到“待审批”记录，批准；客服刷新审批结果，再“确认模拟受理”。
5. 指出同一申请显示“模拟已受理”、真实退款未执行、实际退款金额未确认。打开会话记录可回到原流程。

讲解重点：这里有订单行/数量、政策资格、条件澄清、版本确认、独立审批、模拟受理及历史恢复，不只是调用查单接口。

## 演示二：证据和实际字段不足时说明边界（约2分钟）

1. 新流程使用正常订单和规则；在“商品状态原话”填“没用过，只拆了外包装。”，启动核对。
2. 展示候选原话需要用户确认；临时改成“其实用过一次。”，原确认失效。改回后确认候选，可得到预览，但此时停止本次跟进，不提交申请。
3. 新需求填“只想知道实际退款金额是多少，不要提交。”，启动核对。
4. 展示“未进入申请确认”和“实际退款金额 · 尚无实际字段可核实”，没有预览确认按钮。商品价值不能替代实际退款金额。

讲解重点：原话候选不是激活/质检事实，政策片段也不是实际退款结果。这是信息边界验收，不是证明任意无证据问句都能被准确识别。

## 演示三：质量分支及用户更正约束（约3分钟）

1. 读取`orders.quality_window.number`：实际签收约10天，已使用。选择`defect_policy_id`，退货分支选“质量问题退货”，填原因并启动。
2. 展示等待独立缺陷判定，不能仅凭用户自述或照片认定缺陷。客服创建当前商品行及数量的演示质检工单。
3. 审批员选择该工单，填写处理说明并开始演示质检，再登记“独立缺陷判定：确认缺陷”。这是人工演示登记，不连接真实质检设备。
4. 客服刷新质检核对，得到质量分支预览；展示该分支30天条款与独立缺陷条件。
5. 用户改成“无理由退货”，同时将规则改成`policy_id`。旧确认立即失效；重新核对后提示未使用条件不满足等限制，不再提供确认入口。

讲解重点：质量分支30天不会自动延长无理由7天，独立缺陷结论也不免除另一分支条件。这里验证的是分支、更正和写入边界，不是把附上引用当成答案正确。
